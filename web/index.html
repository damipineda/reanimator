Reanimator: Lunar Lander

A decompiled Flash/AS2 simulation (PhET's Lunar Lander), rebuilt as editable HTML5/JS, with a measured (not claimed) equivalence check against the original. Everything on this page is read from already-generated, cached files - no API key, no live LLM call, no network request other than this page's own same-origin files.

ScenarioHand-built referenceAI-only rebuild (3 repeated runs)Outcome

soft-landing 1.08 m/s, softLanded 4.5 m/s, hardLanded - 4.5, 4.5, 4.6 DIVERGES

The AI-only rebuild loads and plays with zero console errors in all 3 scenarios, and matches the hand-built reference on 2 of 3. soft-landing diverges consistently (3/3 runs). Root cause, confirmed by logging thrust/altitude over time in both rebuilds: not input handling (both register all 7 Up-arrow presses identically, reaching full thrust at the same wall-clock time) and not a physics-formula bug (an idealized, browser-free simulation of both physics.js files lands at nearly the same speed, ~1.83 m/s, both softLanded) - it's a gap in THIS TEST's own synchronization: the hand-built rebuild's clock starts exactly when the test clicks its Start button; the AI-only rebuild auto-starts during its own page load, before the test's clock begins, giving it an unaccounted head start that lands every scripted keypress relatively later on its own internal timeline. Not a bug in the Rewriter's output - a bug in how this specific test measures an auto-starting app. Separately, a multi-round investigation into how the REAL original behaves on this same scripted scenario went through three corrected methodology bugs of its own (a ~220ms click-settle delay, then OCR work delaying the scripted keypresses themselves) before landing on a properly aligned measurement: with that fixed, the original DOES land, softly, across 3 repeated runs (1.0, 0.7, 1.1 m/s) - matching the hand-built reference's own category, though the exact magnitude still differs (original ~0.5-1.0 m/s vs. the hand-built rebuild's ~0.2-1.1 m/s depending on the run) by more than measurement noise alone explains - documented as a real, unresolved gap rather than tuned away. Full numbers and the full account of each methodology correction: verifier report, "Hand-built reference vs. AI-only rebuild", "Measurement noise floor", and docs/KIRO_NOTES.md.
